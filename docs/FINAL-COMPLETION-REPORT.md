## Automatic Criterion Mapping

Task contracts now carry stable criterion and verifier IDs. Runtime validation rejects duplicate criterion/verifier IDs, malformed criteria, empty verifier strings, and references to nonexistent verifiers. A criterion may have no references; that required criterion evaluates to `UNPROVEN`.

The Evidence Engine attaches verifier-backed deterministic evidence to each criterion, then computes the final outcome. Required verifier failure yields `FAIL`; every required reference passing with valid evidence yields `PASS`; an unmapped or insufficiently evidenced required criterion yields `UNPROVEN`. The agent cannot choose the receipt outcome. Receipt validation recomputes mappings/outcomes, binds criterion evidence to canonical task verifier results, and rejects forged PASS, fabricated verifier evidence, unknown evidence/verifiers, and inconsistent diffs.
