# Agent Adapter

`CodexAgentAdapter` is W2's production agent adapter. It invokes the installed `codex exec --json` CLI with the supported `workspace-write` sandbox and the task workspace as its working directory. The engine depends on the `AgentAdapter` boundary: `startRun`, `sendTask`, `receiveAction`, `receiveOutput`, and `cancel`.

JSONL output recognized by the adapter is retained as ordered `agent_output` events. Recognized command/tool items become tool-call records. The adapter does not observe every native operation or file read. Non-zero exit, process errors, or timeout become infrastructure errors; an agent's final text cannot set the receipt outcome.

## Interactive Codex TUI hooks

The PowerShell `w2` launcher hands off to a small W2 Node process adapter, which starts the ordinary `codex` TUI with per-invocation overrides for Codex's native [`UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PermissionRequest`, `Stop`, `Interrupt`, and `SessionEnd` hooks](https://developers.openai.com/codex/hooks). The command hooks consume Codex's structured stdin JSON. `UserPromptSubmit` returns bounded additional context through the documented `hookSpecificOutput` response. On Windows the generated command uses Codex's `command_windows` override and a PowerShell-encoded invocation so `cmd.exe` does not reinterpret quoted paths. It inherits the console and forwards Codex arguments. After hook review and trust in Codex, `UserPromptSubmit` records `HEAD`, the index tree, the working-tree tree, and dirty-path fingerprints in a pending record under `.w2/interactive/<project-hash>/pending/<session-hash>/<turn-hash>.json`. The working-tree tree is built with a temporary Git index outside the project; the user's index, working tree, refs, and history are not changed.

`PreToolUse` stores safe input field names, relative project paths, byte count, hash, and a deterministic command category when available. `PostToolUse` correlates by `tool_use_id` and records only structured status, exit code, response size, and hash. Raw command text and response bodies are not persisted by default. `PermissionRequest` returns no decision, leaving Codex's normal approval flow intact; it never auto-approves or auto-denies. `Interrupt` and `SessionEnd` preserve unfinished calls as interrupted and finalize pending turns as `ABORTED`. At `Stop`, W2 compares the committed range and current Git status with that baseline, filters unchanged pre-existing dirty paths, and persists the turn's Git diff even if the agent already committed and the working tree is clean. It then discovers conventional package scripts and sends an internally captured task through the same `RunEngine`, verifier runner, evidence mapper, outcome calculation, and receipt writer used by manual runs. Safe start/completion metadata is appended to `.w2/interactive/hook-diagnostics.jsonl`.

`InteractiveHookAdapter` records the Stop event and latest assistant message for context. That message is not evidence, and this adapter does not send a second prompt to Codex. It does not read or parse Codex transcripts. Supported hook-delivered tool activity is recorded in the existing tool-call/event and receipt pipeline, but does not prove acceptance criteria. Codex's Stop event ends an assistant turn, not an entire multi-turn product task, so receipts describe one captured turn. A small session index relates those turn receipts without computing a session result. The prompt-action filter is deterministic and conservative, but remains a capture filter rather than proof. Only Git-visible changes and detected `test`, `typecheck`, `lint`, and `build` package scripts are automatically captured. Project checks prove only that those commands passed; without direct verifier mappings to the prompt's semantic requirements, the receipt remains `UNPROVEN`. Browser and visual automation scripts are excluded, including scripts that invoke them transitively.
