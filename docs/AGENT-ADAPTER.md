# Agent Adapter

`CodexAgentAdapter` is W2's production agent adapter. It invokes the installed `codex exec --json` CLI with the supported `workspace-write` sandbox and the task workspace as its working directory. The engine depends on the `AgentAdapter` boundary: `startRun`, `sendTask`, `receiveAction`, `receiveOutput`, and `cancel`.

JSONL output recognized by the adapter is retained as ordered `agent_output` events. Recognized command/tool items become tool-call records. The adapter does not observe every native operation or file read. Non-zero exit, process errors, or timeout become infrastructure errors; an agent's final text cannot set the receipt outcome.

## Interactive Codex TUI hooks

The PowerShell `w2` launcher hands off to a small W2 Node process adapter, which starts the ordinary `codex` TUI with per-invocation overrides for Codex's native [`UserPromptSubmit`, `Stop`, `Interrupt`, and `SessionEnd` hooks](https://learn.chatgpt.com/docs/hooks). On Windows the generated command uses Codex's `command_windows` override and a PowerShell-encoded invocation so `cmd.exe` does not reinterpret quoted paths. It inherits the console and forwards Codex arguments. After hook review and trust in Codex, the prompt hook stores a Git snapshot and a pending record under the deterministic W2 installation root `.w2/interactive/<project-hash>/pending/<session-hash>/<turn-hash>.json`. The Stop hook matches both Codex IDs, compares the snapshot, discovers conventional package scripts, and submits an internally captured task to the same `RunEngine`, verifier runner, evidence mapper, outcome calculation, and receipt writer used by manual runs. Safe start/completion metadata is appended to `.w2/interactive/hook-diagnostics.jsonl`.

`InteractiveHookAdapter` records the Stop event and latest assistant message for context. That message is not evidence, and this adapter does not send a second prompt to Codex. It does not read or parse Codex transcripts. Codex's Stop event ends an assistant turn, not an entire multi-turn product task, so receipts describe one captured turn. The prompt-action filter is heuristic. Only Git-visible changes and detected `test`, `typecheck`, `lint`, and `build` package scripts are automatically captured. Project checks prove only that those commands passed; without direct verifier mappings to the prompt's semantic requirements, the receipt remains `UNPROVEN`. Browser and visual automation scripts are excluded.
