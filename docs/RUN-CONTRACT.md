# Run Contract

`RunEngine` persists one run in SQLite. A run has `run_id`, `task_id`, state, timestamps, model, workspace, context manifest, tool events, diff, verification results, and error.

States are `CREATED -> PREPARING -> RUNNING -> VERIFYING -> COMPLETED|FAILED`; `ABORTED` and `ERROR` are terminal failure states. `RunStore.transition` rejects every transition not in this graph. A verification failure is `FAILED`, never `COMPLETED`.

The `runs` row is the operational summary; normalized `tasks`, `events`, `tool_calls`, and `verification_results` rows remain queryable after the process exits.

Interactive TUI runs construct the same task contract in memory from a likely engineering prompt. A Codex `UserPromptSubmit` hook stores the prompt, baseline `HEAD`, index tree, working-tree tree, and Git status; the matching `Stop` hook combines commits since that baseline with current staged, unstaged, and untracked paths. It filters paths that were already dirty at prompt time unless Git shows additional turn changes. The receipt's unified diff compares the baseline working tree with the Stop-time tree; staged-only evidence is added from the index tree, so committed changes remain visible after the worktree is clean. Snapshot trees use a temporary Git index and do not change the user's index, worktree, refs, or history. W2's built-in `V-W2-TURN-DIFF` verifier proves whether changed paths exist. An explicitly headed acceptance list is copied into individual required criteria. Available non-browser `test`, `typecheck`, `lint`, and `build` package scripts are run and recorded as project-check evidence. A criterion is directly mapped only when it states that a discovered command passes; other semantic criteria remain `UNPROVEN` unless their task contract names a suitable deterministic verifier. A failed referenced verifier remains `FAIL`, and hook or verification infrastructure failures remain `ERROR`. No transcript text, completion claim, or unverified model judgment can produce `PASS`.

These receipts cover one assistant turn, not the full lifetime of a multi-turn request. The canonical runtime root is W2's installation directory at `.w2/interactive/`; project pending state, the shared SQLite run store, and JSON/Markdown receipts stay under `.w2/interactive/<project-hash>/`, while safe hook metadata is appended to `.w2/interactive/hook-diagnostics.jsonl`. The runtime never resolves from the target project's cwd and does not create a project-local `.w2/`. The explicit `w2 run <task.json>` contract remains unchanged.

Supported Codex `PreToolUse` and `PostToolUse` events enter the same adapter, `RunEngine`, `RunStore`, event, and receipt path as other recognized activity. W2 correlates calls by `tool_use_id` and stores safe field/path/size/hash metadata, not raw command input or response bodies. Tool activity is activity evidence only. A call without a matching post event remains incomplete; `Interrupt` or `SessionEnd` marks it interrupted before producing an `ABORTED` turn receipt.

When the optional brainw2 vault is available, `UserPromptSubmit` can add bounded selected project reference context. The receipt records only its logical source, content hash, byte count, and mapping ID. After the receipt is persisted, W2 attempts an idempotent Dev Log summary; any vault error is isolated from the run outcome. A per-session index relates turn receipts but never computes a session-level outcome.
